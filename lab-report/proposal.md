## 2. 项目概述与目标

### 2.1 项目概述

本项目围绕 rCore 用户态控制台输出，整理调用封装，完善参数检查和边界测试，支持简单用户程序输出自定义字符串，并提供可重复的验收脚本，便于调试与演示。

### 2.2 主要目标

| 目标 | 实现内容 | 预期效果 | 验收方法 |
| --- | --- | --- | --- |
| G1 | 整理输出接口和用户态封装，复用已有 `sys_write` 路径 | 基线记录已有输出功能；目标提供单次最多 1024 字节的项目级封装，成功返回实际字节数，已有能力直接复用 | 对照预期字节检查普通字符串、中文字符串、跨页字符串和长度边界用例的输出与返回值 |
| G2 | 完善用户缓冲区检查和错误返回 | 基线逐项记录异常请求的处理结果；目标对非法描述符、超长请求、地址溢出、未映射地址和非用户可读页面返回约定错误码，检查失败时不输出缓冲区内容 | 执行异常用例，检查错误码，并在每次失败后执行一次合法输出，确认内核仍可继续服务 |
| G3 | 提供可重复的验收入口 | 基线记录已有专项用例及通过数量；目标提供 `make check-write`，一条命令完成 12 项接口测试并给出通过数量 | 全部 12 项通过，原有课程测试继续通过；连续运行 3 次结果一致 |

项目按两周左右的课程期末作业安排，围绕一个输出接口开展，复用已有页表、Trap 和控制台输出代码。演示范围限定为单个用户程序、固定地址空间和标准输出，不扩展文件系统、调度器或通用文件描述符管理。

## 3. 设计方案

- 修改模块：
  - 系统调用分发模块：复用已有输出调用路径，检查参数传递和返回值写回。
  - 控制台输出模块：完善参数检查和错误码；已有检查直接复用。
  - 进程及内存管理模块：通过当前用户页表查询地址映射和权限。
  - 用户程序模块：增加项目级输出封装和测试程序；必要时调整链接布局，构造跨页测试缓冲区。
  - 构建与测试脚本：增加专项测试入口，收集输出、返回值和超时结果。具体文件位置以固定后的课程基线为准。
- 核心机制：
  - 采用 RISC-V 现有 `ecall` 路径传参：`a7` 保存调用号，`a0`～`a2` 保存参数，`a0` 接收返回值。复用基线输出调用号，不另建一套调用机制。
  - 项目级封装只接受 `fd = 1`，单次最多 1024 字节；限制在封装层检查，保留底层原有接口的能力。首先检查描述符，再检查长度上限；合法描述符下的零长度请求直接返回 0，不访问缓冲区。
  - 对非空请求使用 `checked_add` 检查地址范围溢出，并限制地址位于有效用户地址范围。逐页检查映射有效且具有 `U`、`R` 权限，拒绝仅内核可访问的页面。
  - 完整检查后，将数据按页复制到固定的 1024 字节内核缓冲区，再复用现有 UART 字节输出路径。只读页面可以作为输出来源，不要求页面具有写权限。
  - 输出按字节处理，不要求缓冲区以零结尾；中文按 UTF-8 原始字节传输，返回值表示字节数。错误码约定为：非法描述符 `-9`、非法地址或权限 `-14`、长度超限 `-22`。
- 关键流程：用户程序准备字符串 → 调用用户态封装 → `ecall` 进入内核 → 校验描述符和长度 → 检查并复制用户缓冲区 → UART 输出 → 写回返回值 → 返回用户态继续执行。
- 技术难点：
  - 用户虚拟地址不能直接当作内核指针使用：通过用户页表得到物理页，利用已有内核物理内存映射完成复制。
  - 字符串可能跨页且后一页不可访问：先检查完整范围，再复制和输出，避免先输出一部分才发现地址错误。
  - 正常输出和测试日志可能混杂：为用例添加明确标记，测试脚本按用例区间检查输出和返回值，避免只查找一个 `PASS` 字样。

## 4. 分类要求

#### 4.1.2 核心创新点

#### 4.1.3 对比基线、评测指标及预期提升

不适用。工程基线、功能目标和回归要求见下节。

### 4.2 工程型

#### 4.2.1 当前工程问题

课程中的控制台输出功能可以作为项目基础，但期末演示还需要明确的接口约定、边界用例和可重复的验收过程。本项目重点整理用户态封装，检查非法地址及跨页缓冲区的处理行为，并形成统一测试入口。

实施前先核对固定基线：已经具备的输出和检查能力直接复用，仅补齐缺失部分；已有功能不计作新增成果。项目工作量主要来自接口整理、边界处理与测试交付。

#### 4.2.2 代码量、使用难度或性能的改进目标

| 方面 | 当前基线 | 项目目标 | 验证方法 |
| --- | --- | --- | --- |
| 功能可用性 | 实施前记录原有接口及 12 项用例的通过情况 | 提供 1 个项目级输出封装，支持单次 0～1024 字节及合法跨页缓冲区，12 项用例全部通过 | 在同一环境比较基线与项目版本的逐项测试结果 |
| 使用难度 | 实施前记录原有调用方式及测试步骤 | 用户程序通过统一封装输出字符串；专项测试统一为 1 条命令 | 运行两个输出不同字符串的用户程序，并执行 `make check-write` |
| 代码规模 | 复用现有 Trap、页表和 UART 实现 | 预计新增或修改约 200～400 行 Rust 与测试脚本，不含文档和自动生成文件；只作为工作量估计 | 使用 `git diff --stat` 记录实际变更，并说明与估计的差异 |
| 性能与资源 | 以固定 commit 的原始程序为对照，数值在实施时测量 | 不设加速目标；保持原有测试超时配置，新增路径不分配堆内存，常驻静态缓冲区不超过 1024 字节 | 在相同环境运行原有测试，检查新增路径及缓冲区声明，记录 ELF 可加载段大小变化 |

#### 4.2.3 功能等价及性能回归要求

- 保留原有输出系统调用的调用号和合法请求行为，项目级封装的长度及描述符限制不改变底层接口对其他程序的支持，原有课程测试全部通过。
- 在相同 QEMU 参数和构建模式下，基线版本与修改版本分别运行原有回归测试 3 次；修改版本每次均须在原脚本的等待预算内完成，不增加超时上限。
- 专项测试使用独立测试程序运行，避免额外输出影响原有结果检查。专项脚本每次运行设置 15 秒超时，失败时保存日志并返回非零退出码。
- 对返回错误的请求，不输出其缓冲区内容；错误返回后能执行合法调用，并继续处理时钟和 UART 中断。
- 本项目不承诺吞吐量或启动速度提升。构建体积和原有测试耗时均记录基线与修改后的实测值，用于说明改动成本，不将预期值写作已完成结果。

## 5. 验证与交付

### 5.1 测试环境

- 宿主环境：优先沿用课程实验的 Ubuntu 24.04 环境，使用普通个人电脑，无额外硬件要求。
- 工具链：采用固定基线要求的 Rust/Cargo 版本，目标为 `riscv64gc-unknown-none-elf`，在交付文档记录可复现版本。
- 模拟器：参考 QEMU `8.2.2`，使用 `qemu-system-riscv64`。
- 启动配置：采用固定基线配套的 QEMU 启动命令，记录机器型号、内存、核心数和固件配置；基线与项目版本使用相同参数。
- 辅助工具：Make、Shell、`rust-objdump`；如使用 Python 检查原始输出字节，记录 Python 版本。

### 5.2 测试方法

**正确性测试：**围绕项目级封装设置以下 12 项用例，各用例检查返回值；涉及输出的用例同时检查实际输出字节。表中错误用例均使用非零长度，另有说明的除外。

| 编号 | 测试内容 | 预期结果 |
| --- | --- | --- |
| T1 | 单页 ASCII 字符串 | 输出内容一致，返回字符串字节数 |
| T2 | UTF-8 中文字符串 | 输出字节一致，返回 UTF-8 字节数 |
| T3 | 跨两个合法用户可读页的字符串 | 按原顺序完整输出，返回请求长度 |
| T4 | `fd = 1`、空指针、长度为 0 | 返回 0，不访问地址、不输出内容 |
| T5 | 合法缓冲区，长度恰好为 1024 | 完整输出，返回 1024 |
| T6 | 长度为 1025 | 返回 `-22`，不输出内容 |
| T7 | `fd` 不为 1，其他参数合法 | 返回 `-9`，不输出内容 |
| T8 | 空指针，长度为 1 | 返回 `-14`，内核继续运行 |
| T9 | 地址位于未映射的 guard page | 返回 `-14`，内核继续运行 |
| T10 | 地址位于已映射但没有 `U` 权限的 TrapContext 页 | 返回 `-14`，不泄露页面内容 |
| T11 | 起始地址接近 `usize::MAX`，长度不超过 1024，但地址加长度溢出 | 返回 `-14`，不尝试读取内存 |
| T12 | 缓冲区前一页合法、后一页未映射 | 返回 `-14`，前一页内容也不输出 |

跨页用例通过页对齐的用户测试数据构造；需要特殊权限或未映射页面时使用独立测试镜像，避免改变原有回归程序。T6～T12 每项结束后再输出一条合法的确认消息，验证错误处理后仍能返回用户态继续执行。

**回归与资源检查：**先检出固定基线运行其配套回归测试并保存结果，再对修改版本重复相同检查；记录每次耗时、通过情况和 ELF 可加载段大小。项目专项测试连续执行 3 次，要求每次均为 12/12 通过。所有实测结果在实现完成后填写。

**实施安排：**第一周完成接口约定、单页输出和参数检查；第二周完成跨页处理、12 项测试、原有功能回归及交付文档。

### 5.3 最终交付

1. 代码：输出接口的必要完善、用户态封装、测试程序及 `make check-write` 入口，保留原有测试入口。
2. README：说明基线 commit、构建与运行步骤、接口参数、1024 字节限制、返回值及错误码。
3. 测试结果：提供 12 项测试的预期值与实测值、3 次重复运行记录、原有功能回归日志和资源变化记录。
4. 演示：展示普通字符串输出、合法跨页输出、非法地址返回错误后继续正常输出三个场景。
